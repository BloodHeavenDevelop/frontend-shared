## 1. Заякоренный попап `.hm-popup` (§15.2) — отсутствует

Манифест §15.1/§15.2 описывает `<UiPopupBox>`/`<UiPopupContainer>` как **заякоренный**
плавающий бокс (проп `anchor`, `min-width:200px`/`max-width:320px`, `box-shadow`,
`z-50`). Фактические `PopupBox`/`PopupContainer` — это система **модалок** (центрированный
оверлей `z-100`, `.hm-modal`), управляемая popup-менеджером (контракт в README).

Решить одно из:
- построить отдельный примитив заякоренного попапа (коллизия имени `<UiPopupBox>`,
  сейчас ноль потребителей), **или**
- поправить манифест под факт: на этой платформе подтверждения/контекстные действия
  делаются через модалки, заякоренный попап не используется.

## 2. Словарь вариантов Badge (§12.1) — расходится

Манифест документирует только `--ok` / `--error` / `--default`. Компонент эмитит
`hm-badge--{success|warning|pending|error|info|custom}`. Классы `.hm-badge--*` с v0.3.0
живут в `assets/styles/hm-base.css` слоя, но значения пропа — часть API вызовов во всех
фронтах: переименование (`success`→`ok`, `custom`→`default`) ломает call-sites.

Нужна скоординированная правка: `hm-base.css` + согласованное изменение API и call-sites
в потребителях.

## 3. Контракт `.hm-input` у FormInput / FormSelect / TableInput

Обёртки над Nuxt UI; точная отрисовка (цвета/границы/паддинги `.hm-input`, §10.4/§10.7.1)

Проверить, что app.config во всех фронтах рендерит контракт `.hm-input` пиксель-в-пиксель.

## 4. Красная точка невалидных строк в EnvBulkInput (§10.8)

Манифест: невалидные строки `KEY=VALUE` получают красную точку в gutter, плюс счётчик
валидных пар снизу. Сейчас `parseEnvContent` возвращает только валидные пары — данных о
невалидных строках нет. Требуется доработка парсера (возвращать и невалидные строки) +
gutter-индикатор. Счётчик валидных пар уже выводится.
